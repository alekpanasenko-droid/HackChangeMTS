# Energytool — веб-консультант

Прототип чата для кейса МТС. Использует локальную базу знаний и код RAG из `MGTS_hackathon-main`, системный промпт пользователя, сохраняет все диалоги и формирует заявку внутри приложения.

## Запуск

1. Распакуйте предоставленный организаторами `MGTS_hackathon-main.zip` рядом с `app.py`: нужна папка `MGTS_hackathon-main/knowledge-base`. Документы базы знаний не входят в публичный репозиторий по условиям кейса.
2. Скопируйте пользовательский `Системный промпт.txt` в корень проекта под именем `system_prompt.txt`. Он также не публикуется в репозитории.
3. Для Yandex AI Studio скопируйте свой `.env` с `YC_API_KEY` и `YC_FOLDER_ID` в корень проекта. Приложение само использует адрес `https://ai.api.cloud.yandex.net/v1` и модель `gpt://<YC_FOLDER_ID>/yandexgpt/latest`. Альтернатива: создайте `.env` по `.env.example` для OpenAI или локальной Qwen.
4. Запустите `docker compose up --build`.
5. Откройте `http://localhost:8000`.

Ключ нужен **от выбранного провайдера модели**. Строка `openai` в зависимостях означает Python SDK, а не выдаёт ключ. Для Yandex AI Studio используются `YC_API_KEY` и `YC_FOLDER_ID`; для OpenAI нужен ключ проекта OpenAI Platform; для локальной Ollama ключ не нужен. `.env` и `system_prompt.txt` исключены из Git. Секреты читаются только на сервере и не передаются в браузер.

## Сценарий проверки

Спросите, например, как найти потери электроэнергии на предприятии. Ответ учитывает предыдущие сообщения. Спустя несколько реплик появляется предложение связаться с менеджером. Нажмите «Оставить заявку», заполните тестовые ФИО, телефон и компанию. В панели «Отладка» видны время ответа и процитированные фрагменты базы. «Новый диалог» начинает чистую сессию, а кнопка «История» показывает все прежние диалоги, включая разговоры без заявки.

## Архитектура

FastAPI обслуживает веб-страницу и JSON API. Поиск использует исходный `rag/rag_pipeline.py`, если создан его FAISS индекс. Без индекса работает лексический BM25 по тем же Markdown-файлам из архива; это позволяет проверить интерфейс без скачивания весов BGE-M3. Для семантического поиска соберите индекс по инструкции `MGTS_hackathon-main/rag/README.md` и задайте `RAG_INDEX`. Генерация идёт через OpenAI-совместимый `/chat/completions`; в запрос передаются системный промпт, история и найденные фрагменты. Модель возвращает текст и ID использованных источников; сервер проверяет ID. SQLite хранит сессии, сообщения, время, источники и заявки в `data/energytool.sqlite3`.

Для встраивания на сайт можно поместить чат в iframe или использовать `/api/*` из собственного виджета. Заявки сейчас доступны через `/api/leads`; для CRM достаточно заменить обработчик сохранения заявки на вызов её API. Реальной отправки контактов нет.

## Ограничения

Без доступной LLM консультация недоступна. BM25 менее точен, чем исходный FAISS+BGE-M3. Для хакатона используйте только тестовые персональные данные. В проекте нет аутентификации: перед публичным размещением добавьте доступ к истории и заявкам по ролям.
