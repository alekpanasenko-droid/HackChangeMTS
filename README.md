# Energytool — веб-консультант

## ZIP для автоматической проверки

Выполните `python tools/build_platform_zip.py`. Скрипт соберёт `output/energytool-platform-submission.zip` с `solution.py` и `requirements.txt` непосредственно в корне. В `solution.py` войдёт локальный `system_prompt.txt`; API-ключи, папка базы знаний, вопросы и веб-приложение в архив не попадут. На платформе `solution.py` использует переданные организаторами `DATA_DIR`, адрес прокси, служебный ключ и идентификатор Qwen3.8-27B из окружения, затем создаёт `submission.csv`.

Прототип чата для кейса МТС. Это самостоятельный веб-интерфейс без авторизации, отдельных режимов пользователей и сотрудников и интеграции с действующим сайтом. Он использует локальную базу знаний и код RAG из `MGTS_hackathon-main`, системный промпт пользователя, сохраняет диалоги и формирует заявку внутри приложения. Стартовый экран предлагает посмотреть направления EnergyTool или описать задачу для подбора решения.

## Запуск

1. Распакуйте предоставленный организаторами `MGTS_hackathon-main.zip` рядом с `app.py`: нужна папка `MGTS_hackathon-main/knowledge-base`. Документы базы знаний не входят в публичный репозиторий по условиям кейса.
2. Скопируйте пользовательский `Системный промпт.txt` в корень проекта под именем `system_prompt.txt`. Он также не публикуется в репозитории.
3. Для Yandex AI Studio скопируйте свой `.env` с `YC_API_KEY` и `YC_FOLDER_ID` в корень проекта. Приложение само использует адрес `https://ai.api.cloud.yandex.net/v1` и модель `gpt://<YC_FOLDER_ID>/yandexgpt/latest`. Альтернатива: создайте `.env` по `.env.example` для OpenAI или локальной Qwen.
4. Запустите `docker compose up --build`.
5. Откройте `http://localhost:8000`.

Ключ нужен **от выбранного провайдера модели**. Строка `openai` в зависимостях означает Python SDK, а не выдаёт ключ. Для Yandex AI Studio используются `YC_API_KEY` и `YC_FOLDER_ID`; для OpenAI нужен ключ проекта OpenAI Platform; для локальной Ollama ключ не нужен. `.env` и `system_prompt.txt` исключены из Git. Секреты читаются только на сервере и не передаются в браузер.

## Сценарий проверки

Спросите, например, как найти потери электроэнергии на предприятии. Ответ учитывает предыдущие сообщения. Если поиск не даёт достаточной опоры, оркестратор задаёт уточняющий вопрос. Спустя несколько реплик появляется предложение связаться с менеджером. Нажмите «Оставить заявку», заполните тестовые ФИО, телефон и компанию, затем скачайте PDF-резюме. В панели «Отладка» видны время ответа, решение оркестратора и использованные фрагменты базы. «Новый диалог» начинает чистую сессию, а «История диалогов» показывает все прежние диалоги, включая разговоры без заявки.

## Архитектура

FastAPI обслуживает веб-страницу и JSON API. `SearchAgent` использует исходный `rag/rag_pipeline.py`, если создан его FAISS индекс. Без индекса работает лексический BM25 по тем же Markdown-файлам из архива; это позволяет проверить интерфейс без скачивания весов BGE-M3. Для семантического поиска соберите индекс по инструкции `MGTS_hackathon-main/rag/README.md` и задайте `RAG_INDEX`. `OrchestratorAgent` оценивает релевантность найденного: при слабой опоре просит уточнить задачу, иначе передаёт историю и фрагменты модели через OpenAI-совместимый `/chat/completions`. Модель возвращает текст и ID использованных источников; сервер проверяет ID. `SummaryAgent` делает структурированное резюме по сохранённым репликам и создаёт PDF с кириллическим шрифтом. SQLite хранит сессии, сообщения, решения агентов, время, источники и заявки в `data/energytool.sqlite3`; PDF-файлы лежат в `data/leads/`.

Заявки доступны через `/api/leads`, PDF — через `/api/leads/{id}/pdf`. Реальной отправки контактов нет. Для оценки качества ответов используется отдельный ZIP из раздела выше: его `requirements.txt` содержит только библиотеки, необходимые `solution.py`, с закреплёнными версиями. Платформа устанавливает их сама и оценивает ответы из `submission.csv`.

## Проверка кода

После установки зависимостей запустите `python -m unittest discover -s tests -v`. Тесты проверяют решение оркестратора при слабой и достаточной опоре, структуру резюме и путь от чата до скачивания PDF. Внешняя модель в тестах заменена заглушкой.

## Ограничения

Без доступной LLM ответы на найденные вопросы недоступны. BM25 менее точен, чем исходный FAISS+BGE-M3, а оценка уверенности поискового агента эвристическая. Резюме формируется по репликам без дополнительных предположений. Для хакатона используйте только тестовые персональные данные. В проекте нет аутентификации: перед публичным размещением добавьте доступ к истории, заявкам и PDF по ролям.
